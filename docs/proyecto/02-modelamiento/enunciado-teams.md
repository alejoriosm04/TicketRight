## Instructions

Avance del proyecto integrador - Entregable 2

| Resumen | Porcentaje | Nota |
|---|---|---|
| Modelo de dominio completo | 5% | Diagrama que muestra las entidades del dominio, sus atributos, relaciones y reglas de negocio |
| *ADR (Architectural Decision Record) - basado en el archivo de excel* | 25% | Documento que registra las decisiones de arquitectura con su contexto, alternativas, motivación y consecuencias. |
| Arquitectura de referencia | 20% | Vista de alto nivel de la solución, con sus capas, componentes, tecnologías y patrones |
| Arquitectura de implementación | 20% | Detalle técnico de cómo se despliegan los componentes, integraciones, infraestructura y configuraciones. |
| Diagrama de clases (para un caso de uso) | 5% | Representa las clases, atributos, métodos, y relaciones para un caso específico del sistema |
| Diagrama de secuencias (para un caso de uso) | 5% | Muestra la interacción entre objetos y el flujo de mensajes en un escenario específico. |
| Prototipo de interfaz de usuario | 10% | Diseño funcional de las pantallas principales que muestran la experiencia de usuario (UI/UX) |
| Plataforma de observabilidad (Incluir métricas de negocio y métricas técnicas) | 5% | Monitoreo, métricas, trazas y logs, para garantizar la operación, rendimiento y resiliencia del sistema. |
| Plan de pruebas unitarias sobre casos de uso definidos | 5% | Estrategia, casos y resultados de pruebas unitarias, que validan el correcto funcionamiento del código. |
| Definición de volumetría para pruebas | 0% | Estimación de volúmenes de datos, usuarios y transacciones para escenarios de prueba |
| Módulo de inyección de fallos | 0% | Mecanismo para simular fallos y validar la resiliencia del sistema |
